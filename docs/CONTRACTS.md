# Shared module contracts

These are the only shared interfaces the portal and admin lanes may rely on during parallel implementation. Data dictionaries use the database field names from the implementation plan (`ItemId`, `Type`, `Title`, `Category`, `Location`, `ItemDate`, `ImageUrl`, `Tags`, `Caption`, `ReporterName`, `ReporterEmail`, `Status`, and `CreatedAt`).

```python
# shared/config.py
APP_MODE: str  # one of: "mock", "local", "cloud"
def get_secret(name: str) -> str: ...

# shared/db.py
def init_db() -> None: ...
def create_item(data: dict) -> int: ...
def get_item(item_id: int) -> dict | None: ...
def list_items(
    type: str | None = None,
    category: str | None = None,
    keyword: str | None = None,
    status: str | None = None,
    reporter_email: str | None = None,
    limit: int = 50,
) -> list[dict]: ...
def update_item_status(item_id: int, status: str) -> None: ...
def delete_item(item_id: int) -> str | None: ...
def create_match(lost_id: int, found_id: int, score: float) -> int: ...
def list_matches(item_id: int | None = None, status: str | None = None) -> list[dict]: ...
def update_match_status(match_id: int, status: str) -> None: ...
def get_stats() -> dict: ...

# shared/storage.py
def upload_image(file_storage) -> str: ...
def delete_image(url: str) -> None: ...

# shared/vision.py
def analyze_image(image_bytes: bytes, category_hint: str = "") -> dict: ...

# shared/matching.py
def score(item_a: dict, item_b: dict) -> float: ...
def find_and_store_matches(new_item_id: int) -> list[dict]: ...
```

## Behavioral guarantees

- `init_db()` creates the local SQLite schema only in mock mode; cloud/local modes connect to Azure SQL.
- `create_item()` returns the persisted item ID. `delete_item()` returns the image URL to remove, if any.
- Item status is one of `open`, `matched`, or `returned`; match status is `suggested`, `confirmed`, or `rejected`.
- `analyze_image()` returns `{"tags": list[str], "caption": str}`. Mock mode provides deterministic safe fallback values and needs no Azure credentials.
- Matching uses `0.6 * Jaccard(tags) + 0.3 * same_category + 0.1 * same_location`; candidates at or above `0.4` are stored.
- All database calls return plain dictionaries/lists suitable for Flask templates and JSON responses.
